- **做法**：

## 四、高频面试题与回答要点

### A. 大模型 / RAG（必问）

1. **RAG 的完整流程？**
   文档解析 → 分块 Chunking（父子分块保留上下文）→ Embedding → 向量库（Milvus/Qdrant/pgvector）→ 召回（向量 + BM25 混合检索）→ Rerank 重排 → 拼 Prompt → LLM 生成。强调混合检索解决专有名词遗漏、Rerank 提升精度。

2. **如何缓解幻觉？**
   RAG  grounding（答案必须引用检索片段）、Prompt 约束（无依据就回答"不知道"）、Self-Reflection/自我检查、输出格式约束（JSON 便于校验）、知识库数据治理、结果可溯源（Citations）。

3. **Dify 这类平台的生产瓶颈？**
   内置 RAG 深度不足（复杂 PDF/图表解析弱）、增量更新残留陈旧向量、默认约 10 QPS 撑不住生产（需调优工作进程/连接池/日志分离，冲 500 QPS 要系统性改造）、高度耦合难深度定制。策略：80% 普通应用放 Dify，20% 核心 RAG 链路用 LangChain/LlamaIndex 自研。

4. **如何评估 RAG 效果？**
   检索侧：Recall@K、MRR、NDCG；生成侧：忠实度(Faithfulness)、答案相关性、上下文精确率；用评测集 + LLM-as-Judge，关注 token 成本与延迟。

### B. Agent / 多智能体（你的主战场）

5. **ReAct vs DAG 工作流 vs 图状态机？各自适用？**
   ReAct：模型自己决定下一步，适合探索性/模糊任务；DAG：代码控制流转、大模型只当节点工人，适合企业审批流、客服，确定性强；图状态机（LangGraph）：代码定义节点/边/条件，兼顾可控与循环分支。真实系统常是"DAG 划边界 + 关键节点放单体 Agent"。

6. **多 Agent 为什么容易翻车？怎么规避？**
   死循环烧 token、上下文传递损耗、结论冲突。规避：Manager-Worker 主从、消息总线、形式化辩论/优先级抢占、超时重试与心跳保活、OpenTelemetry 可观测。记住数据：多 Agent 在代码分析读任务可带来约 90% 质量提升，但 token 消耗约 15 倍——**要用在刀刃上**。

7. **MCP 是什么，解决了什么问题？**
   统一的工具调用标准（基于 JSON-RPC 的 C/S 架构：Host/Client/Server），让模型"懂"怎么调工具，开发者写一个 MCP Server 就能暴露本地文件/DB/API。已成为行业事实标准，跨模型兼容。

8. **Agent 的长期记忆怎么做？**
   向量库 RAG（写入管线 + 召回管线）+ 知识图谱/GraphRAG（多跳关系）+ 经验记忆（把成功轨迹总结成 SOP 存库，"老带新"）。

9. **Agent 沙箱如何做安全隔离？**
   五维度：cgroups（CPU/内存）、Namespace（网络/文件）、Seccomp/AppArmor（系统调用）、临时文件系统；高安全场景用 gVisor/Firecracker 微虚拟机；叠加 HITL 人工审批、权限最小化、白名单。

10. **上下文太长/token 太贵怎么办？**
    滑动窗口、动态裁剪与拼接、小模型摘要压缩、Prompt Caching（命中部分成本可降约 90%）、上下文压缩；工具返回截断/文本提取。

### C. 推理与 AI Infra

11. **vLLM 为什么快？** PagedAttention（KV Cache 分页管理，减少碎片）、连续批处理（Continuous Batching）、张量并行。对比 TensorRT-LLM（FP8 量化、低延迟）、llama.cpp（GGUF 量化、CPU/边缘）。

12. **量化/蒸馏怎么做？** LoRA/QLoRA（显存需求对照：7B QLoRA 约 8-12GB，7B 全量微调约 80GB）、INT8/FP16/FP8、模型蒸馏。端侧优先 1-2B + Q4 量化 + 合理 `-ngl` 分层加载。

13. **分布式并行？** TP（张量切分）、PP（按层切分）、DP（多副本）、ZeRO（优化器状态切分）、混合精度、梯度检查点。

### D. Java / 基础（别丢分）

14. **大表优化？** 索引设计（覆盖索引/最左前缀）、分页优化（延迟关联）、分区分表、冷热分离、Explain 分析、避免 select *。*（注意：你笔记里明确列入了这道题）*

15. **异构数据源事务传播？** Seata AT/TCC/Saga 模式、本地消息表、可靠消息最终一致性（RocketMQ 事务消息）、TCC 的 Try/Confirm/Cancel 与幂等/空回滚/悬挂问题。

16. **Redis 为什么快？** 单线程 + I/O 多路复用 + 纯内存 + 高效数据结构；穿透/击穿/雪崩治理；Cluster 分片。

17. **线上排查框架**：现象确认 → 指标观测 → 缩小范围 → 提出假设 → 实验证伪 → 定位根因 → 修复 → 复盘沉淀。量化表达：优化前 QPS/P99/CPU → 优化后 QPS/P99/CPU。

### E. 行为 / 架构思维

18. **为什么从 Java/工程转 AI？** 强调不是"追热点"，而是工程能力迁移：微服务/分布式 → Agent 编排与多智能体；缓存/CDN → 上下文与记忆；搜索 → RAG；RPC → 工具调用/MCP。AI 系统要落地，缺的正是工程化的人。

19. **做架构如何权衡？** 用"确定性 vs 概率性"框架：代码兜底不确定性；先单体 ReAct 跑通，再按瓶颈演化；优先级：可控 > 炫技。

20. **最近半年学了什么？** 讲 LangGraph/MCP/Agent 沙箱/推理优化的具体实践 + 你自己的 AI 情报平台作为"学习输出"证据。
